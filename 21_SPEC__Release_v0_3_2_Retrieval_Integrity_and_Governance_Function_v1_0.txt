============================================================
1. PROBLEM STATEMENT
============================================================

Even with enforced structure (Σ) and stability gating (ΓΘ), the system can still
produce misleading authority if retrieval evidence is:
- empty (no evidence)
- duplicated (phantom reinforcement)
- dispersed across areas (weak dominance)
- contaminated (evidence not matching chosen dominant coordinates)

In addition, governance is currently a mix of clamps + penalties. This makes it
hard to reason about behavior, test monotonicity, and prevent confidence drift.

v0.3.2 addresses BOTH, staged:

A) Retrieval Integrity: make evidence accounting explicit and enforce invariants.
B) Governance Function: compute governance deterministically from evidence + penalties.

============================================================
2. SCOPE OVERVIEW (A → B)
============================================================

2.1 A — Retrieval Integrity (mandatory)
Introduce an internal Evidence Accounting record and retrieval invariants:
- evidence_count
- unique_side_ids
- unique_hex_ids (optional if available)
- unique_families
- unique_areas
- dedupe_rate
- dispersion metrics (simple ratios; no heavy math required)

These are used ONLY for guards and governance computation and logs.
They are NOT exposed in API response.

2.2 B — Governance Function (mandatory)
Replace ad-hoc governance adjustments with a deterministic function:

governance = f(volume, uniqueness, dominance, dispersion, gammaPenalty, loopability)

Then apply Theta and degraded rules as final caps.

============================================================
3. RETRIEVAL INTEGRITY (A) — REQUIREMENTS
============================================================

3.1 Evidence Object (internal)
Implement an internal structure (dict or dataclass) produced by retrieval:

EvidenceStats:
- evidence_count: int >= 0
- unique_side_ids: int >= 0
- unique_areas: int >= 0
- unique_families: int >= 0
- dedupe_rate: float in [0,1]
  dedupe_rate = unique_side_ids / max(evidence_count, 1)
- area_histogram: map area -> count (optional but recommended)
- family_histogram: map family -> count (optional but recommended)

3.2 Retrieval Invariants (normative)
Enforce the following invariants before any dominance decision:

R1. evidence_count == 0
- must trigger DEGRADED_STATE

R2. dedupe_rate below threshold (default D_MIN = 0.60)
- triggers WARN, may trigger DEGRADED_STATE if also evidence_count < E_MIN

R3. dominance minimum evidence (default E_DOM_MIN = 3)
- If chosen dominant_area has < E_DOM_MIN supporting items -> DEGRADED_STATE

R4. contamination check (optional if metadata allows)
- If a retrieved item claims area/family that is non-canonical -> DATA_REJECT
  (do not HARD_STOP entire request if other evidence exists)

3.3 Observability (logs only)
Must log per request (info level):
- evidence_count
- unique_side_ids
- dedupe_rate
- unique_areas
- dominant_area_support_count (if histogram available)
- degradedFlag

If request fails due to Σ HARD_STOP, API layer must log exception class + message.

============================================================
4. GOVERNANCE FUNCTION (B) — REQUIREMENTS
============================================================

4.1 Deterministic Governance Core
Define these intermediate scalars (all must be clamped to [0,1]):

V (volume score):
- V = min(1, evidence_count / E_SAT)
  Default E_SAT = 12

U (uniqueness score):
- U = dedupe_rate

D (dominance score):
- If area_histogram present:
    D = dominant_area_count / max(evidence_count, 1)
  Else:
    D = 0.5 (conservative fallback)

S (spread penalty):
- If unique_areas known:
    spread = (unique_areas - 1) / (AREAS - 1)     in [0,1]
    S = 1 - spread
  Else:
    S = 0.5

G (gamma stability multiplier):
- G = 1 - gammaPenalty

L (loopability multiplier):
- L = clamp(loopability, 0, 1)

Core governance (before Theta cap):
- governance_raw = V * U * D * S * G * L

Then:
- governance = clamp(governance_raw, 0, 1)

4.2 Theta Gate Integration (normative)
Theta must not be bypassed.
Theta applies the same final constraints as v0.3.1:
- governance := governance * (1 - gammaPenalty)   (if not already in G)
  If governance_raw already used G, do not double-apply; choose one path.
  Normative requirement: gammaPenalty reduces governance exactly once.

4.3 Degraded-State Integration (normative)
Degraded triggers remain from v0.3.1 PLUS retrieval triggers from Section 3:

Degraded if ANY:
- evidence_count == 0
- gammaPenalty >= 0.60
- loopability <= LOOP_DEGRADED_MAX
- dominant_area_count < E_DOM_MIN
- (optional) dedupe_rate < D_MIN AND evidence_count < E_MIN

On degraded:
- governance := min(governance, G_DEGRADED_MAX)
Defaults remain:
- G_DEGRADED_MAX = 0.30
- LOOP_DEGRADED_MAX = 0.20

============================================================
6. ACCEPTANCE CRITERIA
============================================================

A) Retrieval Integrity
- EvidenceStats exists and is computed per request.
- dedupe_rate is computed and bounded.
- evidence_count == 0 triggers DEGRADED_STATE deterministically.
- If dominant_area_count < E_DOM_MIN -> DEGRADED_STATE.

B) Governance Determinism
- governance is computed via explicit f(...) with documented defaults.
- governance is monotonic:
  - increases with evidence_count up to saturation, holding others constant
  - decreases with gammaPenalty, holding others constant
  - decreases as unique_areas increases (more spread), holding others constant

C) Guard Ordering
- Sigma → Gamma → Theta order preserved.
- Σ still enforces contract shape and domain clamps after all adjustments.

D) Tests
Minimum tests (must be in CI):
- governance monotonicity with evidence_count
- governance reduction with gammaPenalty
- dominance threshold triggers degraded
- dedupe_rate low triggers warn and/or degraded per thresholds
- evidence_count 0 triggers degraded cap
