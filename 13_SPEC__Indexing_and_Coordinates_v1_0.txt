Glossary references (see `ACADEMIC.md`):

This document defines the canonical indexing and coordinate model
for the HESPERIA hex-sphere geometry. It is aligned with:
- geometry constants in `11_BLUEPRINT__HESPERIA_v4_7_full.txt`
- Java-style geometry math in `20_GEOMETRY__formalized_structure_java.txt`

All definitions here are normative and should be treated as the
single source of truth for Areas/Families/Hexes/Sides indexing.

============================================================
1. GEOMETRY CONSTANTS
============================================================
// Java-style constants

final int AREAS = 12;
final int FAMILIES_PER_AREA = 24;
final int HEXES_PER_FAMILY = 250;
final int SIDES_PER_HEX = 6;

// Derived counts

final int TOTAL_FAMILIES = AREAS * FAMILIES_PER_AREA;      // 288
final int TOTAL_HEXES    = TOTAL_FAMILIES * HEXES_PER_FAMILY; // 72,000
final int TOTAL_SIDES    = TOTAL_HEXES * SIDES_PER_HEX;    // 432,000

final int SIDES_PER_FAMILY = HEXES_PER_FAMILY * SIDES_PER_HEX;   // 1,500
final int SIDES_PER_AREA   = SIDES_PER_FAMILY * FAMILIES_PER_AREA; // 36,000


============================================================
2. CANONICAL COORDINATE SYSTEM (4D)
============================================================
Each atomic truth slot is a **side** of a hex.
Every side is addressed by a 4D 0-based coordinate:

    area        ∈ [0..11]   // Area band on the ring
    familyLocal ∈ [0..23]   // Family index within the Area
    hexIndex   ∈ [0..249]   // Hex index within the Family
    sideIndex  ∈ [0..5]     // Side index within the Hex

Interpretation:
- area: position along the semantic ring (AREA_RING_ORDER defines traversal).
- familyLocal: wedge / sector inside that Area.
- hexIndex: radial position inside the family lattice.
- sideIndex: orientation of the hex edge (clockwise 0–5).

Family indices also exist in a **global** 0-based space:

    int familyGlobal = area * FAMILIES_PER_AREA + familyLocal; // [0..287]

This global family index is useful for contiguous storage and for
matching existing TOTAL_FAMILIES = 288 math.


============================================================
3. LINEAR SIDE INDEX (sideId ∈ [0..431_999])
============================================================
For arrays like:

    double[] tau     = new double[TOTAL_SIDES];
    int[]    areaOf  = new int[TOTAL_SIDES];
    int[]    familyOf = new int[TOTAL_SIDES];

we use a single canonical **sideId** in [0, TOTAL_SIDES).

3.1 Forward mapping: (area, familyLocal, hexIndex, sideIndex) → sideId

Java-style:

    int familyGlobal = area * FAMILIES_PER_AREA + familyLocal; // [0..287]

    int sideId = (
        ((familyGlobal * HEXES_PER_FAMILY) + hexIndex) * SIDES_PER_HEX
    ) + sideIndex; // [0..431_999]

Order of nesting (slowest → fastest changing):
    familyGlobal → hexIndex → sideIndex

This implies:
- All sides of one Family form a contiguous block of size SIDES_PER_FAMILY (1,500).
- All sides of one Area form a contiguous block of size SIDES_PER_AREA (36,000).

3.2 Inverse mapping: sideId → (area, familyLocal, hexIndex, sideIndex)

Java-style:

    int sideIndex = sideId % SIDES_PER_HEX;
    int tmp       = sideId / SIDES_PER_HEX;

    int hexIndex     = tmp % HEXES_PER_FAMILY;
    int familyGlobal = tmp / HEXES_PER_FAMILY;

    int area        = familyGlobal / FAMILIES_PER_AREA;
    int familyLocal = familyGlobal % FAMILIES_PER_AREA;

Sanity checks:
- sideId ∈ [0, TOTAL_SIDES)       → valid coordinates within ranges above.
- Converting coord → sideId → coord is identity.

3.3 Relationship to tau, areaOf, familyOf

- tau[sideId]     ∈ [0,1] is the truth value of that side.
- areaOf[sideId]  = area  (from inverse mapping).
- familyOf[sideId] = familyGlobal (from inverse mapping).

Thus, all side-local arrays are keyed by the same canonical sideId.


============================================================
4. HUMAN-READABLE SIDE LABEL
============================================================
For logs, manuals, and human reasoning we define a stable,
sortable label:

    Aaa-Fff-Hhhhh-Ss

Where:
- Aaa = 1-based Area number, zero-padded to 2+ digits.
- Fff = 1-based Family index within Area, zero-padded.
- Hhhhh = 1-based Hex index within Family, zero-padded (width ≥ 3).
- Ss = 0-based sideIndex (0..5), unpadded or 1-digit.

Example:

    // Internal 0-based:
    area        = 2
    familyLocal = 4
    hexIndex    = 119
    sideIndex   = 3

    // Human-readable:
    "A03-F05-H120-S3"

4.1 Forward mapping: coord → label

    int area1        = area + 1;
    int familyLocal1 = familyLocal + 1;
    int hexIndex1    = hexIndex + 1;

    String label = String.format("A%02d-F%02d-H%03d-S%d",
                                 area1, familyLocal1, hexIndex1, sideIndex);

4.2 Inverse mapping: label → coord

    // Parse integers from pattern Axx-Fyy-Hzzz-Ss
    int area1, familyLocal1, hexIndex1, sideIndex;

    area        = area1 - 1;
    familyLocal = familyLocal1 - 1;
    hexIndex    = hexIndex1 - 1;
    // sideIndex used as parsed (already 0-based).

This label is purely for humans and logging. It is always derivable
from coord or sideId, and never the other way around exclusively.


============================================================
5. OPTIONAL PACKED SIDE CODE (32-BIT)
============================================================
For compact routing or messaging we can store the full coordinate
in a single 32-bit int using bit fields.

Required bits:
    area        : 4 bits (0–11)
    familyLocal : 5 bits (0–23)
    hexIndex    : 8 bits (0–249)
    sideIndex   : 3 bits (0–5)
Total: 20 bits (fits safely in 32-bit int).

Suggested layout (LSB → MSB):

    [ area(4) | familyLocal(5) | hexIndex(8) | sideIndex(3) ]

Bit-level encoding:

    int encodeSide(int area, int familyLocal, int hexIndex, int sideIndex) {
        return (area        << 16) |
               (familyLocal << 11) |
               (hexIndex    << 3)  |
               (sideIndex);
    }

    int decodeSideIndex(int code)    { return  code        & 0b111; }
    int decodeHexIndex(int code)     { return (code >> 3)  & 0xFF; }
    int decodeFamilyLocal(int code)  { return (code >> 11) & 0x1F; }
    int decodeArea(int code)         { return (code >> 16) & 0x0F; }

This packed code is optional. It must remain a pure function of the
canonical (area, familyLocal, hexIndex, sideIndex) coordinate.

6. JAVA REFERENCE TYPE (SIDE)
============================================================
Reference implementation sketch for Java:

    final class SideCoord {
        final int area;        // 0..11
        final int familyLocal; // 0..23
        final int hexIndex;    // 0..249
        final int sideIndex;   // 0..5

        SideCoord(int area, int familyLocal, int hexIndex, int sideIndex) {
            this.area = area;
            this.familyLocal = familyLocal;
            this.hexIndex = hexIndex;
            this.sideIndex = sideIndex;
        }

        int familyGlobal() {
            return area * FAMILIES_PER_AREA + familyLocal;
        }

        int sideId() {
            int fam = familyGlobal();
            return ((fam * HEXES_PER_FAMILY) + hexIndex) * SIDES_PER_HEX
                   + sideIndex;
        }

        static SideCoord fromSideId(int sideId) {
            int sideIndex = sideId % SIDES_PER_HEX;
            int tmp       = sideId / SIDES_PER_HEX;

            int hexIndex     = tmp % HEXES_PER_FAMILY;
            int familyGlobal = tmp / HEXES_PER_FAMILY;

            int area        = familyGlobal / FAMILIES_PER_AREA;
            int familyLocal = familyGlobal % FAMILIES_PER_AREA;

            return new SideCoord(area, familyLocal, hexIndex, sideIndex);
        }
    }

This Java structure mirrors the logic used in the Python reference
implementation (section 7).

7. PYTHON REFERENCE (SPHERE_RAG.GEOMETRY)
============================================================
The Python reference implementation in sphere_rag/geometry.py
is kept in sync with this document. Core pieces:

    AREAS = 12
    FAMILIES_PER_AREA = 24
    HEXES_PER_FAMILY = 250
    SIDES_PER_HEX = 6

    TOTAL_FAMILIES = AREAS * FAMILIES_PER_AREA
    TOTAL_HEXES = TOTAL_FAMILIES * HEXES_PER_FAMILY
    TOTAL_SIDES = TOTAL_HEXES * SIDES_PER_HEX

    @dataclass
    class HexSide:
        area: int
        family_local: int
        hex_index: int
        side_index: int
        tau: float = 0.0

        @property
        def family_global(self) -> int:
            return self.area * FAMILIES_PER_AREA + self.family_local

        @property
        def side_id(self) -> int:
            fam = self.family_global
            return (((fam * HEXES_PER_FAMILY) + self.hex_index)
                    * SIDES_PER_HEX) + self.side_index

        def human_label(self) -> str:
            return f"A{self.area + 1:02d}-F{self.family_local + 1:02d}" \
                   f"-H{self.hex_index + 1:03d}-S{self.side_index}"

    def side_from_id(side_id: int) -> HexSide:
        side_index = side_id % SIDES_PER_HEX
        tmp = side_id // SIDES_PER_HEX

        hex_index = tmp % HEXES_PER_FAMILY
        fam_global = tmp // HEXES_PER_FAMILY

        area = fam_global // FAMILIES_PER_AREA
        family_local = fam_global % FAMILIES_PER_AREA

        return HexSide(
            area=area,
            family_local=family_local,
            hex_index=hex_index,
            side_index=side_index,
        )

This Python code:
- Implements the exact same mapping as sections 2–3.
- Provides a human-readable label as in section 4.
- Serves as an executable reference for tests and back-checking.


============================================================
8. SANITY CONDITIONS & GUARANTEES
============================================================
For any valid coordinate:

    0 ≤ area        < AREAS
    0 ≤ familyLocal < FAMILIES_PER_AREA
    0 ≤ hexIndex    < HEXES_PER_FAMILY
    0 ≤ sideIndex   < SIDES_PER_HEX

The following must hold:

1) Total count:
   TOTAL_SIDES = AREAS * FAMILIES_PER_AREA
                 * HEXES_PER_FAMILY * SIDES_PER_HEX
              = 432_000

2) Block sizes:
   SIDES_PER_FAMILY = HEXES_PER_FAMILY * SIDES_PER_HEX = 1_500
   SIDES_PER_AREA   = SIDES_PER_FAMILY * FAMILIES_PER_AREA = 36_000

3) Bijectivity:
   - (area,familyLocal,hexIndex,sideIndex) → sideId is injective.
   - sideId → (area,familyLocal,hexIndex,sideIndex) is well-defined
     for sideId ∈ [0, TOTAL_SIDES).
   - Composition in both directions is identity on valid inputs.

4) Compatibility:
   - Java and Python implementations MUST adhere to this spec.
   - Any change to constants or formulas requires updating this
     document and all language bindings together.
