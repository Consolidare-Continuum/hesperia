HESPERIA — SHADOW LAYER v0.3
Controlled Secondary Graph for Diagnostic and Counterfactual Measurement
============================================================

Status:
- Version: v0.3
- Scope: Read-only diagnostic layer
- Dependencies:
    12_SPEC__Semantic_Engine_v0_4.txt

Purpose:
Provide an empirical, controlled, secondary semantic graph
that evaluates Family usage quality, relational richness,
and instability signals without altering base geometry.

------------------------------------------------------------
0. PRINCIPLES
------------------------------------------------------------

P0. Canonical geometry remains authoritative.
P1. Shadow reads from run logs and attribution outputs only.
P2. Shadow produces metrics, flags, and suggestions.
P3. Shadow never rewrites canonical structures.
P4. All computations are deterministic from stored data.

------------------------------------------------------------
1. INPUT CONTRACT (RUN LOG LAYER)
------------------------------------------------------------

For each traversal run r:

struct RunLog {
    long runId;
    long timestamp;

    int dominantArea;       // from StatementAttribution
    int dominantFamily;

    double C_R;             // coherence
    double X_A_R;           // area alignment
    double X_F_R;           // family alignment
    double fragIndex_R;
    double areaEntropy_R;
    double tensionEnergy_R;

    Map<Integer, Double> familyMass; 
    // familyMass[f] = Σ tau[s] for sides in Region R
}

All metrics derive from existing structural math.
No new geometry required.

------------------------------------------------------------
2. SHADOW GRAPH STRUCTURE
------------------------------------------------------------

Nodes:
    Families (0..287)

Edge matrix:
    double W[288][288];  // directed weighted

Initialization:
    W[f][g] = 0 for all f,g

------------------------------------------------------------
3. CHANNEL A — CO-PRESENCE UPDATE
------------------------------------------------------------

For each RunLog r:

Let F_r = set of families with familyMass[f] > 0.

For all ordered pairs (f, g), f != g:

    double m_f = familyMass[f]
    double m_g = familyMass[g]

    double quality =
          C_R
        * X_A_R
        * (1.0 - fragIndex_R)

    double delta =
          m_f * m_g * quality

    W[f][g] += delta

Interpretation:
    Families that co-occur in coherent,
    low-fragmentation regions build weight.

------------------------------------------------------------
4. CHANNEL B — OUTWARD REFERENCE UPDATE
------------------------------------------------------------

For each statement s:

    int f = s.family
    double outwardVector[12]

During a run:

For each family f in region:

    For each area A where outwardVector[A] > 0:

        Identify families g in region where areaOf(g) == A

        For each such g:

            double delta =
                outwardVector[A]
              * familyMass[g]
              * C_R

            W[f][g] += delta

Interpretation:
    Cross-area relations must be supported
    by actual retrieval presence.

------------------------------------------------------------
5. SHADOW METRICS PER FAMILY
------------------------------------------------------------

For each family f:

5.1 Degree mass

    double deg_out = Σ_g W[f][g]
    double deg_in  = Σ_g W[g][f]
    double deg = deg_out + deg_in

5.2 Outgoing distribution

    p_g = W[f][g] / deg_out

5.3 Diversity

    H_out(f) = - Σ_g p_g * log(p_g)

5.4 Stability

Divide runs into batches (time windows or N-run windows).

For each batch b:
    build vector V_b(f) = normalized W_b[f][:]

Stability(f) =
    average cosine similarity between consecutive V_b(f)

Value range:
    [0,1]
    1 = stable relational pattern

5.5 ShadowRichness

    ShadowRichness(f) =
        log(1 + deg)
        * H_out(f)
        * Stability(f)

------------------------------------------------------------
6. DIAGNOSTIC FLAGS
------------------------------------------------------------

6.1 Trash-Bin Flag

Trigger if:
    High usage frequency
    AND low Stability(f)
    AND high H_out(f)
    AND low average X_F_R when dominant

Meaning:
    Family bucket is overloaded / heterogeneous.

6.2 Orphan Flag

Trigger if:
    Moderate frequency
    AND deg below percentile threshold
    AND low H_out(f)

Meaning:
    Family too isolated; possible misplacement.

6.3 Cross-Area Leak Flag

Trigger if:
    Majority of W[f][g] mass goes to
    non-adjacent areas on ring
    AND tensionEnergy_R high when dominant

Meaning:
    Polarity anchoring may be incorrect.

6.4 Thin Classification Flag

Trigger if:
    DominantFamily frequency high
    BUT deg low
    AND low novelty across runs

Meaning:
    Semantically shallow bucket.

------------------------------------------------------------
7. COUNTERFACTUAL SIMULATION
------------------------------------------------------------

For flagged family f:

Simulate move candidate g:

Compute hypothetical region score improvement:

    ΔS =
        avg coherence improvement
        if statements of f were reassigned to g

Shadow does not perform reassignment.
Only reports ΔS estimate.

------------------------------------------------------------
8. OUTPUT REPORT STRUCTURE
------------------------------------------------------------

For each family f:

- Frequency
- ShadowRichness
- Stability
- Top 10 neighbors with weights
- Flag list
- Suggested actions:
    - Split candidate clusters
    - Border move candidate
    - Dictionary tightening suggestion

------------------------------------------------------------
9. HARD CONSTRAINTS
------------------------------------------------------------

Shadow MUST NOT:

- Modify tau[]
- Modify areaOf[]
- Modify familyOf[]
- Modify sideId mapping
- Override governance decisions
- Change ontology tables

Shadow is advisory only.

------------------------------------------------------------
10. INTERPRETATION RULE
------------------------------------------------------------

If many families show low ShadowRichness:
    Corpus insufficient or ontology incomplete.

If specific families show extreme imbalance:
    Ontology or dictionary correction required.

If global richness collapses:
    Structural run instability or logging error.

Shadow is a mirror of empirical relational behavior,
not a new semantic authority.
