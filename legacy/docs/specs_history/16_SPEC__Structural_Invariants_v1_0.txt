1. GEOMETRY CONSTANT INVARIANTS
============================================================

The following constants are frozen for this version:

AREAS = 12
FAMILIES_PER_AREA = 24
HEXES_PER_FAMILY = 250
SIDES_PER_HEX = 6

Derived:
TOTAL_FAMILIES = 288
TOTAL_HEXES    = 72,000
TOTAL_SIDES    = 432,000
SIDES_PER_FAMILY = 1,500
SIDES_PER_AREA   = 36,000

Invariant G1:
Any deviation from these values → HARD STOP.

============================================================
2. INDEXING INVARIANTS
============================================================

2.1 sideId Forward Mapping

familyGlobal = area * FAMILIES_PER_AREA + familyLocal

sideId =
(((familyGlobal * HEXES_PER_FAMILY) + hexIndex)
  * SIDES_PER_HEX) + sideIndex

Invariant I1:
0 ≤ sideId < TOTAL_SIDES

2.2 Inverse Mapping Identity

coord → sideId → coord must be identity.

Invariant I2:
inverse(forward(coord)) == coord

Failure → HARD STOP.

============================================================
3. CARDINALITY INVARIANTS
============================================================

C1:
Each Area contains exactly 24 Families.

C2:
Each Family contains exactly 250 Hexes.

C3:
Each Hex contains exactly 6 Sides.

C4:
No duplicate global family IDs.

C5:
No orphan:
- Side without Hex
- Hex without Family
- Family without Area

Violation → DATA REJECTED.

============================================================
4. ONTOLOGY INVARIANTS
============================================================

O1:

O2:

O3:
Ring order must match canonical AREA_RING_ORDER.

No silent fallback.
No auto-correction.

Violation → REJECT.
