Version: v0.4.0

Model: sentence-transformers/all-mpnet-base-v2 (frozen)

================================================================================
0. Scope
================================================================================

This spec defines the full build stack that turns:

  Dict A (curated ontology anchors)
  Embedding model (offline compiler)
  → Dict B (token → familyGlobal, frozen)
  → Surface Map (token buckets on lexical sides, frozen; hybrid terrain roles)

Runtime traversal uses only frozen artifacts.

================================================================================
1. Goals
================================================================================

- Scale beyond manual Dict B authoring.
- Keep runtime deterministic and auditable.
- Preserve authority separation:
    Dict A = ontology truth
    Dict B = surface lexical coverage
- Create hybrid terrain on the surface:
    lexical anchors do not fill all sides
    preserve decision space for traversal and shadow

================================================================================
2. Non-Goals
================================================================================

This spec does not:
  - introduce runtime AI/LLM inference
  - change traversal math or guards
  - change Dict A altitude semantics
  - "understand" morality or world truth
  - auto-correct Dict A

================================================================================
3. Definitions
================================================================================

3.1 Geometry

  Families: 288 (familyGlobal ∈ [0..287])
  Hexes per family: 250
  Sides per hex: 6
  Sides per family: 1500
  Total sides: 432,000

3.2 Dictionaries

  Dict A: lemma → {familyGlobal, altitude}
  Dict B: token → familyGlobal (+ audit fields in build output)

3.3 Side Roles (Hybrid Terrain)

  Each side has exactly one role:
    L = Lexical anchor side (tokens may attach here)
    T = Transit (neutral movement channel)
    S = Stability/absorption (dampener channel)
    R = Reserved (future hook)

================================================================================
4. Inputs
================================================================================

4.1 Required

  - Dict A native file (current versioned)
  - Candidate vocabulary source(s) for building Dict B
    Examples: extracted tokens from books corpus, curated lists, domain glossaries

4.2 Optional

  - Stoplist (reject tokens like punctuation artifacts, numeric-only, etc.)
  - Multiword term list (kept for later; v0.4.0 focuses on single tokens)

================================================================================
5. Deterministic normalization for build
================================================================================

Build normalization MUST match runtime text normalization rules (v0.3.3):
  - NFKC
  - lowercase
  - whitespace collapse
  - ASCII punctuation stripping (fixed set)
  - length cap is irrelevant in build; token length cap is relevant (see 6.2)

================================================================================
6. Candidate token filtering (before embeddings)
================================================================================

6.1 Reject tokens that are:
  - empty
  - length < 2
  - length > 40
  - numeric-only
  - contain no letters (after normalization)

6.2 Keep tokens that are:
  - alphanumeric with at least one letter
  - stable after NFKC+lowercase normalization

Output of this phase: candidates_clean (deduped set)

================================================================================
7. Embedding model constraints
================================================================================

7.1 Model

  Name: sentence-transformers/all-mpnet-base-v2
  Must be pinned to an immutable revision / hash in the build manifest.

7.2 Execution determinism

  Build environment MUST be frozen:
    - fixed Python version
    - fixed torch version
    - CPU inference preferred
    - embeddings normalized
    - no dropout
  This is not "nice to have". It is mandatory.

================================================================================
8. Anchor set construction (Dict A → anchors)
================================================================================

8.1 Anchor pool

  Anchors are derived from Dict A lemmas.
  Constraints:
    - Each family SHOULD have ≥ A_min anchors
    - Default: A_min = 12
    - If a family has < A_min anchors, it is flagged "thin family".

8.2 Anchor embedding artifact

  Produce and freeze: dict_a_anchors_v040.json
    - lemma
    - familyGlobal
    - altitude (for audit only; not used in similarity)
    - embedding vector (or a binary vector store)

================================================================================
8A. Full Family Affinity Matrix for Dict A (Build-Time Diagnostic Layer)
================================================================================

8A.1 Purpose

  Before classifying Dict B tokens, compute a full semantic affinity matrix:
  For each Dict A lemma L: similarity(L, family_0) .. similarity(L, family_287).
  Produces a 288-dimensional semantic fingerprint per lemma.
  This layer is: build-time only; diagnostic; not used for primary routing or
  runtime traversal.

8A.2 Family representation for affinity

  Option A (default): family_vector_F = mean(embedding(anchors_in_F)).
  Option B (strict): top-K strongest anchors only (K=5). Option A normative for v0.4.0.

8A.3 Affinity matrix construction

  For each lemma L in Dict A: embed lemma; compute cosine similarity against
  all 288 family vectors; normalize similarities to [0,1]; store full vector.

8A.4 Artifact produced

  dictA_family_affinity_v040.json — structure per lemma:
    primary_family, primary_score, full_affinity_vector[288], top5_families,
    OSS (ontology sharpness score).
  Mandatory for build diagnostics.

8A.5 Derived metrics (diagnostics)

  - Ontology Sharpness Score (OSS) = primary_score - second_highest_score.
    Flag if OSS < 0.07 (ambiguous anchor).
  - Family Cohesion Score (FCS): mean intra-family similarity per family.
    Flag if FCS < 0.45.
  - Cross-Family Leakage Index (CFL): how strongly family anchors score
    against other families; detect ontology drift.

8A.6 Hard fail conditions (optional but recommended)

  Build must warn or fail if: 15% of Dict A lemmas have OSS < 0.07; any family
  FCS < 0.40; any two families mean cross-similarity > 0.75.

8A.7 What this does NOT change

  Does not change primary Dict A assignment, altitude, traversal seeding, or
  Dict B classification logic. Purely structural validation and measurement.

8A.8 Additional artifacts (affinity layer)

  - family_vectors_v040.json — familyGlobal, mean embedding vector (frozen).
  - report_dictA_affinity_matrix_v040.txt — OSS distribution, % ambiguous,
    top 20 weakest anchors, FCS per family, CFL top overlapping pairs.
  - report_family_geometry_v040.txt — inter-family similarity summary,
    most similar/isolated families, geometry entropy.
  - dictA_geometry_flags_v040.json (optional) — weak_anchor, family_overlap_flag,
    thin_family_flag per lemma/family.

================================================================================
9. Similarity scoring and assignment (Build Dict B)
================================================================================

9.1 Similarity metric

  cosine similarity over normalized vectors

9.2 Core variables (defaults)

  These defaults are normative for v0.4.0.

  τ (accept threshold) = 0.35
    If top1 < τ → reject token ("semantic vacuum")

  δ (ambiguity margin) = 0.05
    If (top1 − top2) < δ → mark ambiguous

  μ (ambiguity handling mode) = "flag_and_assign"
    Meaning: keep the assignment but flag it.

  K (top-k tracked) = 5
    Store top-5 candidates for audit (family + lemma + score)

9.3 Tie-break rules

  If two candidates have equal top score within float tolerance:
    - choose lowest familyGlobal
    - if same family, choose lexicographically smallest lemma

9.4 Output record per accepted token

  Dict B build record MUST include:
    - token
    - assigned_familyGlobal
    - top1_score
    - top1_anchor_lemma
    - top2_score
    - ambiguous_flag
    - topK list (K=5)

9.5 Rejection record

  Rejected tokens must be logged with:
    - token
    - best_score
    - best_anchor_lemma
    - reason: below_threshold / filtered / other

================================================================================
10. Global distribution controls (anti-collapse)
================================================================================

10.1 Family imbalance cap κ (defaults)

  Prevent a few families absorbing everything.
  κ_max_share = 0.06 (6% of all accepted tokens)
  If any family exceeds κ_max_share:
    - build is marked "FAIL: imbalance"
    - you must fix Dict A anchors or adjust τ
  This is strict for a reason: it protects topology.

10.2 Family minimum presence

  Require that at least F_min_covered = 240 families receive ≥ 1 token
  If not, flag "coverage failure".

================================================================================
11. Build modes (normative presets)
================================================================================

Mode A — Strict
  τ = 0.40, δ = 0.06, μ = "flag_and_reject"
  Use when you want tight ontology and can accept lower coverage.

Mode B — Balanced (DEFAULT)
  τ = 0.35, δ = 0.05, μ = "flag_and_assign"
  Recommended.

Mode C — Exploratory
  τ = 0.30, δ = 0.04, μ = "flag_and_assign"
  Use only to study gaps; expect more noise.

12. Dict B artifact (frozen output)
================================================================================

12.1 Primary output

  dict_b_v040.json

12.2 Audit output (required)

================================================================================
13. Surface siding (Dict B → sides) with hybrid terrain
================================================================================

This part creates the actual "terrain" you asked for.

13.1 Role quotas per family (defaults)

  Per family (1500 sides):
    L = 600 (40%)
    T = 450 (30%)
    S = 300 (20%)
    R = 150 (10%)

13.2 Hex-level constraints (normative)

  For every hex (6 sides):
    L_count ≤ 3
    T_count ≥ 1
  These must always hold.

13.3 Role mask generation

  Each family gets a deterministic role mask over its 1500 local sides.
  Requirements:
    - deterministic per family ID and surface version
    - produces exact quotas in 13.1
    - stable across machines

13.4 Token placement into lexical sides

  Given token t assigned to family F:
    - Determine initial hex and side candidate deterministically from t
    - If candidate side role ≠ L, probe deterministically to next candidate
    - Enforce hex constraint L_count ≤ 3:
        if hex already has 3 lexical sides occupied, probe to next hex
  Collisions:
    - lexical side holds a bucket (list)
    - bucket ordering is deterministic (lexicographic token order)

13.5 Surface artifacts

  Outputs:
    surface_roles_v040.bin/json (role mask)
    surface_map_v040.bin/json (tokens attached to lexical sides)
  Runtime loads these. Never rebuilds them per request.

================================================================================
15. Failure conditions (hard)
================================================================================

Build MUST fail if any occurs:
  - Any family exceeds κ_max_share (6%)
  - Covered families < F_min_covered (240)
  - Any hex violates: L_count > 3 or T_count < 1
  - Role quotas per family not exact
  - Determinism checks fail (same inputs produce different outputs)

================================================================================
16. Runtime integration rules
================================================================================

Runtime must:
  - load dict_b_v040.json
  - load surface_roles_v040 and surface_map_v040
  - never call embedding model
  - never mutate Dict B or surface map

================================================================================
17. Versioning and rebuild policy
================================================================================

Rebuild is allowed only when:
  - Dict A version changes
  - candidate vocabulary changes
  - model revision changes
  - τ/δ/κ parameters change
  - surface role quotas or constraints change

All such changes require bumping: dict_b_v0xx, surface_map_v0xx

================================================================================
18. What you might be missing (common traps)
================================================================================

- Weak Dict A anchors → everything smears
  Fix by adding anchors per family, not by lowering τ forever.

- Ambiguous tokens (bank, charge, apple)
  Flag them; don't pretend they're clean.

- Family collapse (few families absorb most tokens)
  κ cap prevents this; treat failure as a signal.

- Collision explosion (too many tokens per lexical side)
  That's fine early; you can add a bucket cap later, but do it deterministically.

- Language mixing
  If your vocabulary is multilingual, your embeddings and anchors must match
  languages. v0.4.0 assumes English unless stated otherwise.

================================================================================
20. End state
================================================================================

After v0.4.0 build you have a fully frozen stack:
  - Dict A (truth)
  - Anchor embeddings (compiler cache)
  - Dict B (token → family)
  - Surface roles (terrain)
  - Surface map (lexical anchors)

Then traversal and shadow can become "intelligent" through movement,
not through runtime semantics.
