What changed (additive, non-breaking vs v0.3.2)
------------------------------------------------------------

- Deterministic attribution and region seeding. POST /hesperia/analyze now uses request body text.
- Step 0 — Normalize: NFKC, lowercase, deterministic whitespace collapse, hard cap (default 10_000). Reject > cap → 413.
- Step 1 — Tokenize: Whitespace split, strip punctuation (fixed ASCII set only). No heuristic regex; deterministic. No stemming.
- Step 2 — Attribution: Dictionary A (lemma → familyGlobal + altitude) exact match; else Dictionary B (token → familyGlobal). Aggregation: dominant family = argmax(hits); tie-break lowest meanAltitude then lowest familyGlobal. Dominant area = floor(dominant_family / 24).
- Region seed: For dominant family F, seed = all 1500 sides in F; tau = base_weight * hitDensity_F * (1 - meanAltitude_F). attribution_v033.build_region_seed.
- Failure conditions: text missing → 400; length cap → 413; no tokens matched (semantic vacuum) → 400; any metric NaN/Inf → 500.
- Extended metrics (not in minimal 6-key): total_tokens, matched_tokens, unmatched_tokens, attribution_coverage, meanAltitude_global, seed_size.
- Single analysis entrypoint: always guarded pipeline (Sigma → Gamma → Theta). Shadow is a flag passed into the pipeline (shadow_enabled), not a separate entrypoint; when true, shadow layer runs after Theta inside run_pipeline.
- Dictionary A/B: Versioned files; no runtime modification. Dict A native: lemma → {familyGlobal, altitude}. Dict A legacy: lemma → list of {side_id, weight} — first entry only (multi-side across families: first entry wins). familyGlobal = side_id // 1500. Legacy weight = strength (locked): altitude = 1 - clamp(weight). Dict B legacy (side_id → {canonical_lemma, aliases}) inverted to token → familyGlobal.
