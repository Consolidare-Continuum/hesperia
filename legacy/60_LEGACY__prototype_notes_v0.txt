# HEX RAG Sphere — Prototype Spec v0.1

**Purpose.** A closed-loop, interpretable semantic core that routes any text through **12 Areas × 12 Families** on a ring (“hex sphere”), enabling retrieval, reasoning, governance, and coherence control for GPT-class models.

---

## 1) Core Ontology

### 1.1 Areas (antipodal pairs)

* **GOOD ↔ HARM**
* **TRUTH ↔ DECEIT**
* **ORDER ↔ CHAOS**
* **FREEDOM ↔ CONTROL**
* **CARE ↔ INDIFFERENCE**
* **CREATION ↔ DESTRUCTION**

### 1.2 Closed Loop (ring order)

`GOOD → CARE → ORDER → CONTROL → INDIFFERENCE → HARM → DESTRUCTION → CHAOS → FREEDOM → TRUTH → CREATION → GOOD` (wrap-around; sphere closes on itself).

### 1.3 Families (satellites)

Each Area has 12 Families (from the shared working list). Six **edge-families** per Area drive transitions toward each neighbor (document which six for each Area). Families should be:

* **Neutral, portable** (avoid culture-loaded labels)
* **Non-overlapping**, with scoped aliases where necessary (e.g., “Safety (governance)” vs “Psychological safety (GOOD)”).

---

## 2) State & Data Structures

* **A ∈ Δ¹¹**: 12-d Area activation vector (probabilities).
* **F ∈ ℝ¹⁴⁴**: Family activations grouped by Area (conditional on A).
* **O ∈ [0,1]**: Obstacle/risk score (absorbing potential).
* **Meta:** provenance, timestamps, embeddings, span maps.

**Corpus-level:**

* Area centroid **Ā**, per-Area family centroids **\bar Fᵃ**
* Transition matrix **P (12×12)** over the ring (learned from observed transitions)
* Glossary/aliases map: canonical home + scoped aliases

---

## 3) Loop Mechanics (HEX-Limited Loops)

**Inputs:** text span, query, or document.

1. **Score Areas** → A; start at argmax(A).
2. **Score Families** within Area; if a Family dominance **D ≥ τ** (e.g., 0.18), mark **weighted**.
3. **Obstacle check**: if **O ≥ θ** (e.g., 0.25), **BREAK** the loop.
4. **Advance clockwise** to next Area and repeat.
5. **Stop** when: (a) BREAK; (b) 3 full passes with no new weighted families; or (c) convergence (entropy drop / no-new-weights over one pass).

**Counters:**

* **Pass** = 12 hops; max 3 passes (36 hops) unless converged earlier.
* **Loopability L** = (# hops adding a new weighted family)/(# hops).

---

## 4) Obstacles (Heavy Breakers)

Neutral process labels to avoid cultural heat; examples:

* **Lethality/violence:** killing, invasion, eradication
* **Deceptive systems:** gaslighting, false-balance, forgery, astroturfing
* **Catastrophic failure:** irrecoverable data loss, irreversible harm, uncontrolled cascade
* **Governance red lines:** rights violation, unlawful directive, tamper-evidence breach

Obstacles act as **absorbing states**. When triggered (O ≥ θ), the loop halts and emits a structured rationale.

---

## 5) Geometry & Math (no-code operationalization)

### 5.1 Bipolar axes (6D signed space)

For each antipode pair (e.g., GOOD–HARM), compute Bₖ = A⁺ − A⁻. Use for polarity, tension detection, drift tracking.

### 5.2 Ring transport & smoothing

* **EMD/Wasserstein on C₁₂** (wrap-around distance) for comparing A distributions.
* **Graph Laplacian smoothing** over the ring: denoise A/F while respecting adjacency.
* **Sinkhorn (entropic OT)** to blend query and context without spikes.

### 5.3 Spectral/phase tools

* **Fourier on C₁₂**: low-frequency power = thematic coherence; high-frequency = ping-pong.
* **Phase rotation (cyclic shift)**: rotate query A to maximize fit with corpus centroid Ā (phase alignment).
* **Orthogonal rotation in 6D** (Procrustes) to align bipolar axes to principal components without breaking antipodes.

### 5.4 Markov dynamics

* Random walk on ring with transition matrix **P**; spectral gap controls expected pass count.
* **First-passage/return times** provide routing/latency estimates between Areas.

---

## 6) Metrics (instrumentation)

* **Coverage Φ**: fraction of Areas hit ≥ once (target ≥ 0.90 typically)
* **Loopability L**: exploration efficiency per pass
* **Entropy H(A)**, **H(F|A)**: stance sharpness; falling entropy = convergence
* **Curvature κ**: inverse angular dispersion of retrieved chunks (tightness)
* **Tension energy Tₑ**: antipode gap × (1 − evidence)
* **Divergence**: EMD/KL/JS between query and context A
* **Coherence Cₜ**: cosine(Aₜ, Aₜ₋₁) across turns; drift guard
* **Obstacle window**: expected time-to-absorption given O

### 6.1 Query Coherence Score (QCS)

Aggregate: phase-aligned fit, smoothness (Fourier), tension resolved, obstacle safety, family crispness.
`QCS = w·[S₁,S₂,S₃,S₄,S₅]ᵀ` (policy-tunable weights).

---

## 7) Retrieval & Reasoning (RAG integration)

* **Routing:** Use A to select shards/indices; use weighted Families to select exemplars.
* **Prompting:** Inject top (Area,Family) weights as guardrails and rationales.
* **Safety:** Obstacles short-circuit unsafe generations; surface structured “stop reasons.”
* **Attribution:** Log top-3 (Area,Family) per answer for explainability.

---

## 8) Prototype Evaluation (paper run — no code)

Run CW/CCW loops over representative texts (normative rights, commons dilemma, tech-policy). Observe:

* Direction-invariant **attractors** (FREEDOM/ORDER/TRUTH/CARE/GOOD) when normative; bounded negatives (HARM/DESTRUCTION)
* Early surfacing of **FREEDOM↔CONTROL** and **TRUTH↔DECEIT** tensions
* **Obstacles** halting risky debates (e.g., uncontrolled cascade) with rationale
* Convergence ≤ ~2 passes; over-spin only when obstacles disabled

## 9) Development Paths

### Phase A — Spec & Reference Data (0-code → light-code)

* Finalize canonical Families + scoped aliases per Area
* Define obstacle lexicon & scoring rubric
* Author domain defaults for τ (dominance), θ (obstacle), and neighbor edge priors in P
* Curate prototypes (exemplar snippets) per Family for interpretability

### Phase B — Prototype Engine

* Implement Area/Family scoring (embeddings + lexicon hybrid)
* Ring transport (EMD on C₁₂) and phase alignment
* Loop executor with metrics (Φ, L, κ, H, QCS) and obstacle absorption
* Minimal UI: loop trace, weights timeline, obstacle rationales

### Phase C — Learning & Tuning

* Learn P from observed transitions (counts/EM)
* Calibrate τ, θ per domain using convergence/quality targets
* Optimize QCS weights to predict human-rated coherence
* Expand glossaries; reduce leakage via canonical homes

### Phase D — Productization

* RAG routing (index-by-Area/Family), prompt guardrails
* Decision dashboards: tensions, obstacle windows, drift (PSI)
* Governance: policy bands for FREEDOM↔CONTROL and TRUTH↔DECEIT
* APIs for integration with existing GPT pipelines

### Phase E — Scaling & Safety

* Corpus growth: enrich Families; monitor entropy/coverage
* Add uncertainty estimation (Wilson/Jeffreys for dominance)
* Red-team obstacle lexicon; add domain-specific breakers
* Telemetry & SLOs: κ↑, H↓, QCS↑ across releases

---

## 10) Known Risks & Mitigations

* **Family overlap** → canonical home + scoped alias tags; evaluation for leakage
* **Cultural/jargon load** → neutral labels; glossaries; multi-lingual mapping
* **Threshold brittleness** → per-domain calibration; confidence intervals
* **Obstacle false positives** → multi-signal gates (lexical + embedding + source credibility)
* **Path dependence** → direction-dual runs (CW/CCW) and report union

---

## 11) Feasibility & Conclusion

**Feasibility:** High. The core fits a compact, interpretable state (A,F,O) with stable, closed loops and clear halting conditions. Math tools (ring EMD, Laplacian smoothing, Fourier, Markov) are standard and efficient. Early dry-runs show direction-robust convergence and meaningful obstacle halts.

**Utility:** Strong for **coherence control**, **explainable routing**, and **governance**. The HEX-limited loops create a semantic manifold that any GPT model can be steered within, with quantitative metrics (QCS, κ, H, L) for continuous improvement.

**Growth:** The sphere scales by enriching Families and learning transition physics (P) from data without breaking the ontology. It remains human-auditable and policy-tunable, ideal for decision support and context-grinding at corpus scale.

**Bottom line:** Proceed to Phase A immediately. Lock the canonical Families/aliases and obstacle rubric, then build the minimal loop executor and metrics. This will validate the HEX RAG Sphere as the backbone for retrieval, reasoning, and governance in your system.
