HESPERIA
SPEC — Embedding-Based Family Classification Layer (EBFCL)

SUPERSEDED BY: 28_SPEC__v0_4_0_Embedding_Based_DictB_and_Surface_Siding.txt (2026-02-23)

Version: v0.4.0-draft
Status: Build-time only (offline, deterministic)

================================================================================
1. PURPOSE
================================================================================

Define a deterministic, scalable method to construct:

  Dict B:
  token → familyGlobal

using semantic similarity against Dict A anchors, without introducing runtime
probabilistic behavior.

This layer:
  - Assigns lexical surface coverage
  - Does not affect traversal logic
  - Does not run at runtime
  - Produces frozen artifacts

================================================================================
2. SYSTEM POSITION IN STACK
================================================================================

Full pipeline:
  1. Dict A (manual ontology anchors)
  2. Embedding Classification Layer (this spec)
  3. Dict B (frozen mapping)
  4. Surface Builder (hex + side allocation)
  5. Runtime traversal engine

This layer sits between 1 and 3.

================================================================================
3. MODEL SELECTION
================================================================================

Model:
  sentence-transformers/all-mpnet-base-v2

Why:
  - 768-dimensional embeddings
  - Strong semantic separation
  - Good performance on abstract and concrete nouns
  - Stable, widely tested
  - Not excessively large
  - Deterministic under fixed environment

Not allowed:
  - API-based embeddings
  - Generative LLMs
  - Models with dynamic remote weights
  - Auto-updating versions

================================================================================
4. INPUTS
================================================================================

4.1 Dict A (Authoritative Anchors)

  Structure:
    lemma → familyGlobal

  Constraints:
    - Curated manually
    - High semantic clarity
    - No ambiguity across families
    - Balanced coverage across 288 families
    - Each lemma becomes a semantic anchor.

4.2 Candidate Vocabulary

  Sources may include:
    - Word lists
    - Books corpus extraction
    - Domain dictionaries
    - Controlled expansions

  Must be:
    - Tokenized
    - Lowercased
    - Deduplicated
    - Cleaned

================================================================================
5. EMBEDDING STRATEGY
================================================================================

5.1 Embedding Granularity

  Embed:
    - Single-token strings only
    - No sentence wrapping
    - No contextual templates

  Rationale:
    - Avoid bias
    - Avoid artificial framing
    - Keep ontology pure

5.2 Anchor Embedding

  Embed all Dict A lemmas once.
  Output:
    Anchor Matrix A: shape = (N_anchors, 768)
  Store permanently:
    dict_a_embeddings_vX.json

5.3 Token Embedding

  For each candidate token:
    Compute: token_vector ∈ R^768
    Normalize vectors.
  Similarity metric:
    cosine_similarity(token, anchor)

================================================================================
6. FAMILY ASSIGNMENT RULE
================================================================================

For each token:
  - Compute similarity to all anchor lemmas.
  - Find top similarity score.
  - Assign to familyGlobal of best anchor.
  - Store: familyGlobal, similarity score, matched anchor lemma

================================================================================
7. CRITICAL CONTROL VARIABLES
================================================================================

Define explicitly.

7.1 Similarity Threshold (τ)

  Minimum similarity required for acceptance.
  Example range:
    - Conservative: τ = 0.40
    - Moderate: τ = 0.35
    - Broad coverage: τ = 0.30

  If similarity < τ:
    → Reject token (semantic vacuum)

7.2 Ambiguity Margin (δ)

  If: (top1_similarity - top2_similarity) < δ
  Mark token as ambiguous.
  Example: δ = 0.05

  Ambiguous tokens may:
    - Be excluded
    - Be logged for review
    - Be assigned but flagged

7.3 Family Imbalance Cap (κ)

  After classification:
    No single family may exceed: κ = 2.5% – 5% of total Dict B tokens
  If exceeded:
    Review anchors, increase τ, rebalance Dict A
  Prevents semantic gravity collapse.

================================================================================
8. OUTPUT STRUCTURE
================================================================================

Dict B format:

  {
    token: {
      familyGlobal,
      similarity,
      matched_anchor
    }
  }

Frozen as: dict_b_vX.json
Versioned.

================================================================================
9. DETERMINISM REQUIREMENTS
================================================================================

To guarantee reproducibility:
  - Fixed model version
  - Fixed torch version
  - CPU inference preferred
  - No dropout
  - Normalize embeddings
  - No mixed precision
  - Fixed numeric precision

Same inputs → same Dict B → same surface → same traversal.

================================================================================
10. SCALE CONSIDERATIONS
================================================================================

Expected sizes:
  - Dict A anchors: 1k–5k lemmas
  - Candidate vocabulary: 10k–100k tokens
  - Embedding dimension: 768

Compute cost: O(N_tokens × N_anchors)
Acceptable offline.

================================================================================
11. INTEGRATION WITH SURFACE LAYER
================================================================================

After Dict B is frozen:
  Surface builder:
    - Assigns tokens to hexes
    - Enforces: Max 3 L per hex, ≥1 T per hex
    - Builds: surface_map_vX.json

Embedding layer does NOT interact with hex logic.

================================================================================
12. FAILURE CONDITIONS
================================================================================

Abort build if:
  - 30% tokens rejected (τ too strict)
  - 1 family exceeds κ imbalance cap
  - Similarity distribution too flat
  - Anchor coverage insufficient

Generate: classification_report_vX.txt
Including:
  - Acceptance rate
  - Mean similarity
  - Per-family token counts
  - Ambiguity rate

================================================================================
13. WHAT THIS LAYER DOES NOT DO
================================================================================

It does NOT:
  - Perform reasoning
  - Define traversal behavior
  - Modify Dict A
  - Adjust altitudes
  - Affect runtime decisions
  - Use shadow logic

It is classification only.

================================================================================
14. OPTIONS TO RUN
================================================================================

Three modes:

  Mode A — Strict
    High τ, low ambiguity tolerance. Tighter families, lower coverage.

  Mode B — Balanced (recommended)
    Moderate τ. Controlled ambiguity.

  Mode C — Exploratory
    Lower τ. Higher coverage. Requires review.

================================================================================
15. LONG-TERM EVOLUTION
================================================================================

Future improvements may include:
  - Phrase-level embedding for multi-word terms
  - Domain-specific fine-tuning
  - Anchor expansion feedback from traversal metrics

But runtime remains untouched.

================================================================================
16. FINAL ARCHITECTURAL PRINCIPLE
================================================================================

  Embedding layer = compiler.
  Traversal layer = intelligence.
  Surface layer = topology.
  Guards = evaluation.

  No layer invades another.
