PROLOGUE — WHAT THIS DOCUMENT IS
================================================================================

Hesperia did not arrive as a version number. It arrived as a problem: how to
make a Russian TFP scientific statement executable, inspectable, and eventually
teachable — without letting prose leak into parameters, without letting team chat
become product bytes, and without pretending that a git tag equals a live API.

This file is the **evolution tree** — not the autopsy log. The autopsy log is
414 commits wide; this tree is **sixteen cell divisions** wide, each division
named for what it added to the organism: membrane, nucleus, organ, nerve, voice.

Read it when you need to answer:
  • What existed at version X, and what did NOT exist yet?
  • Why did we split prod from dev, brain from product, tersagor from hesperia?
  • What is DONE vs what is deliberately deferred to 0.7.0?
  • Where do bytes live, and who owns the closure?

The metaphor is intentional. Biology keeps structure without lying about history.
A liver does not contain the memory of the zygote — but the lineage is traceable.
Same here: `runtime/shipping/` does not contain the Feb 2026 pivot docs — but
`hesperia-v0.4.0` is still an ancestor commit you can checkout.

§30  SCIENTIFIC INTENT — WHAT HESPERIA IS FOR (STABLE ACROSS CELLS)
================================================================================

  Cells change code; scientific intent changes slowly. Pass 3 states intent so
  version numbers do not obscure the research program.

  CORE PROPOSITION:
    Hesperia executes Translational Formalism Pack (TFP) propagation on Russian
    scientific statements — mapping utterances through layered graphs, dictionaries,
    and dynamics — producing traces and activations operators can inspect.

  STABLE GOALS (Feb → Jun):
    1. Deterministic or gated-deterministic propagation (ΣΓΘ, seals, pytest).
    2. Calibration via dictionaries and contradiction — not one-shot LLM magic.
    3. Inspection before mutation — Inspector, KSI, IRC envelope before apply.
    4. Numeric parameter proposals — Teacher returns weights, not prose lessons.
    5. Corpus on prod disk — sessions and dict JSONL are product, not clutter.

  WHAT HESPERIA IS NOT (repeated because teams forget):
    • Not a chatbot product (Teacher is inspector of parameters, not tutor prose).
    • Not a second brain repo (team workflow stays in cursor).
    • Not a tersagor fork (integration ≠ canonical source after CELL 14).
    • Not finished at 0.6.3 (apply and Pane 2 remain 0.7.0).

  HESPERIA AND CLIENTS/:
    Hesperia is a client under CLIENTS.md with its own product repos; brain holds
    list, paths, deploy pointers — not duplicate product implementation.

  ---------------------------------------------
  schema              const "hesperia.engine_run_envelope.v063"

  correlation_id      ties IRC chunks and MySQL row cluster
  run_id              uuid for this application run
  input.text_ru       operator Russian TFP statement (full visibility on IRC)

  engine.*            propagation_trace, areas, families, tfp_vector,
                      invariant_activation, interior_pov, gtp_coherence,
                      corpus_activations[], roads[], hesperia_ref,
                      integration_host_ref (optional)
  ksi.*               incidents[], missing_bridges[], phi_trace (from analyze)
  parameters.*        W_e edges[], ksi_config_ref

  teacher_request (sanitized — OpenAI input)
  ------------------------------------------
  ksi_version         "0.1"
  session_id          typically run_id
  iteration_id        typically correlation_id
  incidents[]         enriched with incoming_edges
  missing_bridges[]   ranked by bridge_need_score
  topology            optional concept topology block
  *** raw input.text_ru does NOT appear here (Sophia boundary) ***

  hesperia.teacher_response.v063
  ------------------------------
  schema              const "hesperia.teacher_response.v063"
  lang                "ru"
  proposals[]         each with action, confidence, numeric fields
  allowed actions:    add_edge, remove_edge, update_edge_weight,
                      add_concept, update_cd_field
  forbidden keys:     justification, message, explanation, reasoning, comment

  IRC trace JSONL record
  ----------------------
  ts                  ISO UTC timestamp
  channel             e.g. #hesperia-teacher
  type                RUN_START | ENGINE_ENVELOPE | TEACHER_REQUEST |
                      TEACHER_RESPONSE | REWEIGHT_PREVIEW | RUN_DONE
  payload             object or chunked body for large envelopes

  reweight_preview[] (emitted, not applied in 0.6.3)
  ---------------------------------------------------
  parameter_key       e.g. W_e:A->B or concept.field
  value_before        numeric
  value_after         numeric
  applied             0 always in 0.6.3
