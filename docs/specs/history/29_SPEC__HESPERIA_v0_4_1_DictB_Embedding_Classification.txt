================================================================================
1. PURPOSE
================================================================================

Define deterministic construction of Dict B using embedding-based semantic
similarity against Dict A anchors.

Dict B provides:
  token → {
    preferred_family,
    possible_relaxed_family (optional)
  }

Dict B is:
  - Build-time generated
  - Version-locked
  - Runtime immutable
  - Deterministic
  - No runtime embedding calls allowed.

================================================================================
2. MODEL REQUIREMENTS
================================================================================

Embedding model: sentence-transformers/all-mpnet-base-v2

Constraints:
  - Fixed model revision hash
  - CPU inference preferred
  - No dropout
  - Normalized embeddings
  - Fixed Python + torch versions
  - Stored in build_manifest_v041.json

================================================================================
3. INPUTS
================================================================================

Required:
  - dict_a_v0XX.json
  - dict_a_anchors_v040.json
  - family_vectors_v040.json
  - candidate_tokens_v0XX.txt

Candidate tokens must be:
  - NFKC normalized
  - Lowercase
  - Deduplicated
  - Filtered (length 2–40, contains letter)

================================================================================
4. SIMILARITY MECHANISM
================================================================================

Metric:
  cosine_similarity(token_embedding, family_vector)

Family vector:
  Mean embedding of Dict A anchors in that family.

================================================================================
5. CLASSIFICATION VARIABLES (DEFAULTS)
================================================================================

Primary threshold:                    τ = 0.35
Primary separation margin:            δ_min_primary = 0.05
Secondary threshold:                  τ_relaxed = 0.30
Secondary margin limit:               δ_max_secondary = 0.12
Family overlap cap:                   family_overlap_cap = 0.80
Family cohesion minimum:              FCS_min = 0.40
Secondary global cap:                 max_secondary_ratio_global = 0.40
Secondary per-family cap:             secondary_count_F ≤ 0.5 × primary_count_F
Family density cap:                   κ_max_share = 0.06 (6%)

================================================================================
6. ASSIGNMENT RULES
================================================================================

For each token T:
  Compute:
    S1 = highest similarity
    F1 = family of S1
    S2 = second highest similarity
    F2 = family of S2

6.1 Preferred Assignment

  Assign F1 as preferred if:
    - S1 ≥ τ
    - (S1 − S2) ≥ δ_min_primary
    - FCS(F1) ≥ FCS_min
  If not satisfied → reject token.

6.2 Possible_Relaxed Assignment

  Assign F2 as possible_relaxed if ALL hold:
    - S2 ≥ τ_relaxed
    - (S1 − S2) ≤ δ_max_secondary
    - cosine(F1_vector, F2_vector) ≤ family_overlap_cap
    - F2 passes cohesion threshold
  Otherwise: possible_relaxed = null

================================================================================
7. STORAGE STRUCTURE
================================================================================

7.1 Runtime Dict B

  File: dict_b_v041.json
  Structure:
    token: {
      "preferred": familyGlobal,
      "possible_relaxed": familyGlobal | null
    }
  No similarity values stored in runtime artifact.

7.2 Audit Artifact

  File: dict_b_v041_audit.jsonl
  Contains per token:
    S1, S2
    matched family vectors
    anchor references
    FCS(F1)
    ambiguity flags
    rejection reason if rejected

================================================================================
8. DENSITY GOVERNANCE
================================================================================

Build must enforce:
  - No family exceeds 6% primary share.
  - Secondary global ratio ≤ 40%.
  - Secondary per-family cap respected.
  - No family exceeds 600 lexical slots (surface capacity).
If violated → build fails.

================================================================================
9. FAILURE CONDITIONS (HARD)
================================================================================

Build aborts if:
  - 20% tokens ambiguous
  - 10% assigned via weak anchors (OSS < threshold)
  - Any family exceeds κ_max_share
  - Secondary overflow > cap
  - Family cohesion violation detected
  - Total lexical tokens in family > 600

================================================================================
10. REPORTING REQUIREMENTS
================================================================================

Produce:
  - report_dictB_stats_v041.txt
  - report_secondary_affinity_v041.txt
  - family_secondary_matrix_v041.json

Must include:
  - Acceptance rate
  - Rejection rate
  - Ambiguity rate
  - Per-family primary counts
  - Per-family secondary counts
  - Most overlapping family pairs
  - Weak anchor propagation rate

================================================================================
11. SURFACE INTEGRATION RULE
================================================================================

Surface builder MUST:
  - Use only preferred families
  - Ignore possible_relaxed
  - Enforce: max 3 L per hex, ≥1 T per hex
  - No secondary lexical attachment in v0.4.x.

================================================================================
12. RUNTIME RULE (INVARIANT)
================================================================================

When shadow is disabled:
  possible_relaxed must not alter state vector

Test case required:
  Baseline result identical with or without secondary fields.

================================================================================
13. VERSIONING POLICY
================================================================================

Rebuild required if:
  - Dict A changes
  - Candidate vocabulary changes
  - Embedding model revision changes
  - Any threshold parameter changes
  - Family geometry changes

Rebuild must increment: dict_b_v0XX

================================================================================
14. ARCHITECTURAL PRINCIPLE
================================================================================

Dict B classification:
  - Deterministic
  - Geometry-aware
  - Density-governed
  - Dual-family constrained
  - Runtime inert

Embedding model acts as compiler only.
Traversal remains the intelligence engine.
